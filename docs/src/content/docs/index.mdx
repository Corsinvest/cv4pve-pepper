## Why

In Proxmox VE the console of a VM is a few clicks away in the web interface: log in, find the VM, open
*Console*, or download a `.vv` file for SPICE and open it before its ticket expires. That is fine once. It is
not when the same people open the same VMs every day, when a script has to show a console, or when a user
should only get an icon on the desktop, not the whole web interface.

cv4pve-pepper does those steps in one command. It asks the API for a console ticket, writes the file for the
viewer and starts `remote-viewer` with it, so the console can be a shortcut, a line in a script or a menu
entry.

## One command. Any VM. SPICE or VNC.

SPICE for the full desktop experience, VNC for every running VM and container: switch with a single flag.

<Tabs>
  <TabItem label="SPICE">

```bash
cv4pve-pepper --host=pve01 --api-token='pepper@pve!console=…' --vmid=webserver --viewer=/usr/bin/remote-viewer
```

<img src={openSpice.src} alt="remote-viewer showing the SPICE console of container 105, at the login prompt" width="742" />

  </TabItem>
  <TabItem label="VNC">

```bash ins="--vnc"
cv4pve-pepper --host=pve01 --api-token='pepper@pve!console=…' --vmid=webserver --viewer=/usr/bin/remote-viewer --vnc
```

<img src={openVnc.src} alt="remote-viewer titled VNC: CT 105, showing the VNC console of container 105 at the login prompt" width="742" />

  </TabItem>
</Tabs>

1. pepper connects to `pve01` and looks up `webserver` in the cluster, on whichever node it runs.
2. For SPICE it asks Proxmox VE for a SPICE ticket and writes a `.vv` file in the temporary folder; for VNC
   (`--vnc`) it opens a local bridge to the console.
3. It starts `remote-viewer`, which opens the console window and deletes the `.vv` file once read.
4. With SPICE pepper exits at once and the viewer stays open; with VNC pepper keeps the bridge open until you
   close the viewer.

## Where it fits

cv4pve-pepper opens one console, from the command line. Its companion
[cv4pve-vdi](https://corsinvest.github.io/cv4pve-vdi/) is the desktop application for people who pick their
VM from a list. Both use the same console code, so SPICE and VNC behave the same way.

| | **cv4pve-pepper** | [cv4pve-vdi](https://corsinvest.github.io/cv4pve-vdi/) |
|---|---|---|
| **What it is** | Command-line tool | Desktop application |
| **You choose the VM** | On the command line or in a parameter file | From the list of the VMs you may use |
| **Consoles** | SPICE, VNC | SPICE, VNC, plus RDP, SSH and custom services |
| **Login** | API token or user and password, in options or a file | User and password, per person |
| **Best for** | Shortcuts, scripts, one console per icon | Users working on several VMs every day |
| **Access** | Proxmox VE API only, from outside the nodes | Proxmox VE API only, from outside the nodes |

## Outside the nodes, API only

cv4pve-pepper runs on the computer where the console should appear and talks only to the Proxmox VE REST API
on port 8006, plus the SPICE proxy on port 3128 for SPICE. Nothing is installed on the nodes and no SSH is
needed: an account with the privileges in [Permissions](/cv4pve-pepper/permissions/) is enough. Give it more
than one node and it connects to the first one that answers.
